title: "Recipe: connect HyphaeDB to Claude Code"
description: One command wires Claude Code (or any MCP host) to gossip-backed agent memory — the launcher bootstraps the server and the identity itself.
---

**Goal.** Give an MCP host — Claude Code, Codex, Cursor, OpenCode — HyphaeDB as agent memory, so
the agent calls `store` / `recall` / `pull_inbox` as tools instead of speaking gRPC, with **zero
manual auth steps**.

## Install the plugin (recommended)

From a HyphaeDB repo checkout, with Docker running:

```bash
claude plugin marketplace add /path/to/hyphaedb-checkout
claude plugin install hyphaedb@hyphaedb
```

That's the whole setup. The plugin registers the `hyphae` MCP server and ships the
`hyphae-memory` conventions skill. Its server entry runs the launcher:

{/* hyphae-example: examples/mcp/.mcp.json */}
```json
{
  "mcpServers": {
    "hyphae": {
      "command": "node",
      "args": ["${CLAUDE_PLUGIN_ROOT}/launcher/bin/hyphaedb-mcp.mjs"],
      "env": { "HYPHAE_AGENT_NAME": "claude" }
    }
  }
}
```

## How it works

The launcher is a zero-dependency **stdio↔HTTP bridge**: it speaks MCP JSON-RPC on stdin/stdout
to the host and forwards every frame verbatim to the server's `POST /mcp`. On startup it resolves
a server — an explicit `HYPHAE_URL`, else a probe of localhost (`:8081` examples stack, `:8080`
deploy stack), else it brings up the shared examples compose stack itself — and fixes that origin
for the session.

Identity needs no manual step either: the launcher derives a stable identity from your project
directory and agent name, provisions it once over the Dev profile's `POST /v1/dev/provision`, and
caches the credential at `~/.hyphae/launcher/` (0600). Warm starts reuse the cache; every session
of the same project converges on one `dev:` agent per host.

## Use it

Ask the agent to store a memory and recall it — the server stamps authorship from the
authenticated key, never from tool arguments. Non-plugin hosts don't get the `hyphae-memory`
skill, so paste the conventions prompt instead:

{/* hyphae-example: examples/mcp/PROMPT.md */}
```text
You have HyphaeDB memory tools in this session. Follow these conventions:

1. Store durable decisions at high salience (store, salience 0.8 or higher):
   architecture choices, settled disputes, breaking discoveries. Store routine
   notes at low salience (0.2): rebase notes, transient status. Salience drives
   propagation reach — a 0.2 memory travels nowhere, by design.
2. Place beacons for your standing interests (place_beacon): the topics that
   should be routed to you, such as security findings or API changes. Place
   each interest once, not per session.
3. Check your inbox at session start (pull_inbox): drain what the mesh routed
   to you before starting work. The server owns the cursor; a repeat call never
   replays acknowledged items.
4. Recall before starting a work cycle (recall): query memory for prior
   decisions on the task at hand before deciding anew.

Your identity is stamped server-side from your API key; there is no per-call
identity argument.
```

## Launcher-direct (no plugin)

Any MCP host can run the launcher without the plugin — register it as a stdio server:

```bash
claude mcp add hyphae --env HYPHAE_AGENT_NAME=claude -- node /path/to/hyphaedb-checkout/examples/mcp/launcher/bin/hyphaedb-mcp.mjs
```

or in a project `.mcp.json`:

{/* hyphae-example: examples/mcp/hosts/claude-code.md#L25-L33 */}
```json
{
  "mcpServers": {
    "hyphae": {
      "command": "node",
      "args": ["/path/to/hyphaedb-checkout/examples/mcp/launcher/bin/hyphaedb-mcp.mjs"],
      "env": { "HYPHAE_AGENT_NAME": "claude" }
    }
  }
}
```

Per-host snippets (Codex, Cursor, OpenCode, n8n) live in the repo under `examples/mcp/hosts/`.

## Remote / production servers

Auto-provisioning exists only on Dev-profile servers. Against a remote or production server, set
both overrides — an explicit URL and an explicit key:

{/* hyphae-example: examples/mcp/hosts/claude-code.md#L43-L55 */}
```json
{
  "mcpServers": {
    "hyphae": {
      "command": "node",
      "args": ["/path/to/hyphaedb-checkout/examples/mcp/launcher/bin/hyphaedb-mcp.mjs"],
      "env": {
        "HYPHAE_AGENT_NAME": "claude",
        "HYPHAE_URL": "https://hyphae.example.com",
        "HYPHAE_API_KEY": "hyk_your_agent_key"
      }
    }
  }
}
```

## Manual fallback (from source / airgapped)

Without the launcher, the server binary itself speaks MCP over stdio: it is a **per-agent
subprocess** that binds no ports, and identity is fixed for the life of the process — the
`HYPHAE_API_KEY` launch token is resolved once into an authenticated principal and reused for
every `tools/call`. It needs `DATABASE_URL` and the launch token in its environment:

```bash
DATABASE_URL="postgres://postgres:hyphae@localhost:5432/hyphae" \
HYPHAE_API_KEY="hyk_your_agent_key" \
hyphae-server mcp-stdio
```

It reads JSON-RPC on stdin and writes on stdout — you won't see a prompt; that's expected.
Register it with the host:

{/* hyphae-example: examples/mcp/hosts/claude-code.md#L67-L78 */}
```json
{
  "mcpServers": {
    "hyphae": {
      "command": "hyphae-server",
      "args": ["mcp-stdio"],
      "env": {
        "DATABASE_URL": "postgres://postgres:hyphae@localhost:5432/hyphae",
        "HYPHAE_API_KEY": "hyk_your_agent_key"
      }
    }
  }
}
```

Each agent that should have a distinct identity gets its **own** key in its own server entry —
the token is the identity.

<Note>
Over MCP, `recall` and `query` return `{node_id, distance}` pairs, **not** hydrated content — read a
cell's content over a hydrating surface (the [REST API](/api-reference/overview)). This keeps the MCP
tool responses small and id-based.
</Note>
